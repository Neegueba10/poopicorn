# Poopicorn

A js13kGames 2026 entry. Theme: **Rainbows and Unicorns**.

You are a rainbow poppy farmer. The darn pegacorns won't leave them alone! Their poo makes great fertilizer but they're eating your entire crop. Thin the heard by latching on with your trusty hose, pump them full of the good stuff until they pop. Buy upgrades along the way, Survive as long as you can.  
## Controls

| Key | Action |
| --- | --- |
| `A` / `D` or arrows | walk |
| `W` / `S` or arrows | aim the hose |
| `W` / up arrow, `Z` or `N` | jump, and jet while held |
| space, `X` or `M` | fire the hose; hold to pump a latched pegacorn |
| mouse click | start, and unlock audio |
| `R` | retry after a game over |

## Run it

```
npm install
npm start          # dev build + https://localhost:3000 (self-signed cert)
```

```
npm run build          # the full pipeline, writes dist/game.zip
npm run build:zipSize  # prints the zip size and what is left of the budget
npm run test:dist      # loads the built dist/index.html and checks for exceptions
```

`npm run build:zip` needs two system binaries, `advzip` (Debian/Ubuntu package
`advancecomp`) and `ect` (built from source, on `PATH`). Without them the zip
step fails, but `dist/index.html` is still a valid, playable build.

## Authoring the assets

```
npm run tools      # http://localhost:8787
```

A simply dev server runs 3 tools for editing game assets

- **`/sdf` — SDFtool.** Models, sprite sheets and animation clips. A model is a
  short list of 3D primitives — spheres, boxes, capsules, tori — melted
  together and cut apart, raymarched into pixels at boot. A crate is 30
  numbers. Writes `src/js/models/`, `src/js/sheets/` and `src/js/clips/`.
- **`/stage` — Stagetool.** The level editor: an unbounded plane of parallax
  layers holding sprite stamps, box collision and tagged objects. `P`
  playtests a body against the real collision code. Writes `src/js/stages/`.
- **`/soundbox/` — Voxby.** The synth tracker. Export JS from it, then
  `npm run convert-song -- <file>` to turn it into a module under
  `src/js/sounds/`. Voxby is a git submodule; `git submodule update --init`
  after a fresh clone.

Each editor's file format is specified in its own README:
[tools/sdftool/README.md](tools/sdftool/README.md) and
[tools/stagetool/README.md](tools/stagetool/README.md).

## How the game is put together

`src/js/game.js` is the entry point. It makes a palette, hands a 480x270 canvas
to the game module, and runs the frame loop. the art is baked at boot from `src/js/models/` into one
offscreen canvas

- `src/js/games/poppy.js` — the game itself.
- `src/js/core/` — the engine. `sdf.js` raymarches models into palette indices;
  `quant.js` does the colour lookup and the ordered dither; `palette.js`
  generates 256 colours from 96 bytes of ramp endpoints; `sdfsheet.js` bakes a
  sheet into an offscreen canvas; `sdfanim.js` expands a clip into ordinary
  sheet rows; `stage.js` is the large-world runtime; `font.js` is a 5x9 bitmap
  font packed into source; `musicplayer.js` plays the song; `utils.js` holds
  the audio init and the small maths helpers.
- `src/js/models/`, `sheets/`, `clips/`, `stages/`, `sounds/` — the data, all
  of it generated by the editors above.

## The build pipeline

`npm run build` runs, in order: rollup (IIFE bundle) → terser (aggressive,
`unsafe_*` on, top-level mangling) → property crunch
([scripts/crunch-props.js](scripts/crunch-props.js), a second terser pass that
mangles an explicit allowlist of our property names that collide with DOM
builtins) → roadroller (self-extracting packer) → an HTML inliner →
html-minifier-terser → `zip` + `advzip` + `ect`.

`scripts/find-best-roadroller.js` searches for better packer flags. It writes
`scripts/roadroller-config.json`; the `build:roadroller` script carries its
flags inline, so a winning search has to be copied across by hand.

## Tests

```
npm test              # every suite
npm test -- mirror    # only suites whose filename matches
```

The runner boots its own tools server on port 8788, so a dev server on 8787 can
stay open. It drives real pointer and keyboard input over the Chrome DevTools
Protocol and needs `google-chrome` on `PATH` (or `$CHROME`). Some sdftool
suites are pure Node — the SDF runtime has no DOM dependency, and proving that
is half the point.

Run the suites a change can affect after touching `tools/sdftool/`,
`tools/stagetool/` or `src/js/core/`.
